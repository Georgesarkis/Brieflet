# Brieflet

Short, local-written AI context for code repositories. A local model writes a brief (`AI_CONTEXT.md`, a component
diagram, decision records) so a big model like Claude reads fewer tokens and answers faster.

First measurement (22 Nov 2026, eShop, Claude Sonnet, 3 questions × 2 runs): **78k input tokens with the brief vs
158k with no docs and 343k with a raw Graphify code graph**, 30 s vs 54 s. Small sample: the benchmark in
[`bench/`](bench/) exists to test this properly, including answer quality.

## Use

```
pip install requests pyyaml
python -m brieflet init path/to/repo --plan            # what it will do, calls no model
python -m brieflet init path/to/repo                   # local Ollama ($0): qwen3.5:9b labels, Bonsai 27B writes
```

Local-first: the docs are written by a model on your own machine ([Ollama](https://ollama.com)), free, and your
code never leaves it. Other model backends plug in through the `brieflet.llm_backends` entry point group
(see [ARCHITECTURE.md](ARCHITECTURE.md)); a paid backend prints a cost estimate first and needs `--yes`.

Writes `AI_CONTEXT.md`, `CLAUDE.md` (pointer), `docs/architecture/components.md` and `docs/decisions/` + `DECISIONS.md`.
`--out DIR` writes somewhere else instead of into the repo.

**Any language.** The component diagram comes from the code, not from a model:

- **.NET Aspire**: the AppHost (resources, references, endpoints) plus each project's HTTP/gRPC clients.
- **Everything else**: package manifests (`package.json`, `pyproject.toml`, `setup.py`, `requirements.txt`, `go.mod`,
  `Cargo.toml`, `pom.xml`, `build.gradle`, `*.csproj`, `composer.json`, `Gemfile`), Docker Compose services and
  Dockerfiles, entry points (`main.py`, `src/main.rs`, `Program.cs`, start scripts) and dependencies between the
  projects. Known images and client libraries (Postgres, Redis, Kafka, RabbitMQ, …) become infrastructure boxes.
  A repo with no manifests gets one box per top code folder.
- **Big monorepos** (100+ packages): the diagram keeps 15 boxes. Apps and the most used libraries stay, the rest
  become one group box per folder (`packages/*`). Examples, tests, docs and `node_modules` are left out.

Decision records come from what the code shows: Compose, Kubernetes, Terraform, CI, monorepo tools, gRPC/GraphQL
schemas, and dependencies (web framework, database + ORM, message bus, auth, background jobs).
Reading Compose files needs `pip install pyyaml`.

Each generated doc ends with one line: *Generated by Brieflet*, with a link here. Keep it if Brieflet helps you;
`--no-footer` (or `BRIEFLET_FOOTER=0`) leaves it out.

**Self-improving:** it also writes `LEARNED.md`. The `CLAUDE.md` rule tells the assistant: if the docs didn't answer and
you had to search the code, add one line `- <fact> → \`path\`` there. So the next question doesn't dig the same code
again. Every `brieflet init` keeps those lines but drops ones whose file is gone, duplicates and secret-looking text
(max 60 lines).

## Benchmark

```
pip install pyyaml
cp bench/bench.example.yaml bench/bench.yaml     # edit repos, arms, models
python -m bench plan -c bench/bench.yaml         # matrix + cost estimate, spends nothing
python -m bench learn -c bench/bench.yaml        # only for arms with `learn: true`: learning pass per fold
python -m bench run  -c bench/bench.yaml         # free runners only; paid ones need --yes and estimate ≤ max_usd
python -m bench report -c bench/bench.yaml
python -m pytest bench/tests                     # offline tests, no keys
```

Built-in runner: `fake` (offline, checks the pipeline). Reader models and the quality judge are plugins
(`brieflet.bench_runners`, `brieflet.bench_judges` entry point groups); paid ones need a price, `--yes` and
`max_usd`. Compare arms within one model; different runners are different harnesses.

Learning is measured fairly: questions are split in folds (default 2). The arm learns on fold 1 and is measured on
fold 2 with only fold 1's facts, and the other way round, so it never sees facts from the question it is scored on.

Shipped question sets (10 questions each, written before any run, reference points for the judge in `*.refs.yaml`):
`bench/pilot.yaml` = dotnet/eShop (Aspire microservices), `bench/eshoponweb.yaml` = eShopOnWeb (.NET monolith;
none vs Brieflet vs CodeGraph, 30 runs).

Spec and fairness rules: [`bench/SPEC.md`](bench/SPEC.md).
